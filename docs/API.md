# Worklog implementation contract

Owner: root; task WORKLOG-BUILD. Local-only, new repository. Root owns database primitives, work/day/context services and API integration. Plans agent owns plans.py, proposals.py and corresponding tests. Frontend agent owns frontend/. Operations agent owns cli.py, recovery.py, scripts/, README.md and corresponding tests. Shared files require parent coordination. No commits by children.

All API routes start /api/v1. camelCase JSON. UUID ids, integer revision; timestamps UTC ISO strings. Date strings YYYY-MM-DD in configured America/Chicago timezone. States are open, doing, blocked, done. Every mutation sends a JSON object (raw uploads excepted), includes revision for existing records, and an Idempotency-Key header for creates/approval. Error: {error:{code,message,fields?}}. Conflict 409. Envelope lists {items:[...],total:n}; objects returned directly. Session bootstrap POST /session/bootstrap body {} and X-Worklog-Bootstrap: 1 returns {csrfToken,today,timezone}; fetch credentials same-origin, X-CSRF-Token on cookie writes. Agent Bearer credentials cannot mutate canonical endpoints. Health GET /health unauthenticated: {app:'worklog',version,instanceId,dataId,ready:true}. Health outside api prefix.

Final integration additions: bootstrap also returns required dataId, which namespaces all browser drafts/queues/pending idempotency keys. Offline restore rotates dataId and revokes credentials. Legacy/other-context drafts remain untouched and are never imported automatically. /work-items accepts q, roadmapId, bounded limit/offset; list records add isBacklog. POST /work-items/{id}/move {revision:collectionRevision,direction:'up'|'down'} reorders against a server-selected neighbor across pages. Work details include linkedRoadmap {id,title,archived} and linkedStep {id,title,roadmapId,roadmapTitle,retired}. GET /notes/{id}, /tasks/{id}, /references/{id}, /steps/{id} provide bounded review targets. Search results include routeType and routeId. Daily entries retain archived actual work as read-only history. Import commit is idempotent and shares one transaction with search and history. A durable .restore-in-progress.json marker blocks startup after interrupted replacement until an explicit offline restore succeeds.

Item {id,title,description,status,adoUrl,roadmapId,stepId,people:[...],backlogOrder,archived,revision,createdAt,updatedAt}. PATCH /work-items/{id} {revision,...fields}. POST /work-items/{id}/archive or /recover {revision}. POST /work-items/reorder {ids:[all active backlog ids],revision:collectionRevision}. List includes collectionRevision.
GET /days/{date} -> {date,revision,reflection,entries:[{id,itemId,date,planned,worked,outcome,position,revision,item:WorkItem}],summary:{worked:[...],completed:[...],blocked:[...]},nextItemId}. PUT /days/{date}/entries/{itemId} {revision:0 for create or existing revision,planned?,worked?,outcome?}. PUT /days/{date}/reflection {revision:dayRevision,text}. POST /days/{date}/reorder {revision:dayRevision,ids:[entry ids]}. POST /days/{date}/reschedule {itemId,targetDate,revision:entryRevision,targetRevision:0|existing}.
GET /work-items/{id} -> item plus {dailyEntries,notes,tasks,attachments,references,history}. GET /history?entityId=&limit=100 returns list envelope.

## Supporting records
Notes {id,ownerType:'item'|'roadmap'|'step',ownerId,title,text,revision,archived,...timestamps}; POST /notes, PATCH /notes/{id}, POST /notes/{id}/archive|recover. Markdown text, title optional. Tasks similar, {text,done,itemId}; POST /tasks, PATCH /tasks/{id}, archive/recover. References {itemId,path}; POST /references, archive/recover.
Links {id,ownerType:'item'|'roadmap',ownerId,url,title,description,revision,archived,...timestamps}; POST /links, PATCH /links/{id}, archive/recover.
Agent chats {id,ownerType:'item'|'roadmap',ownerId,chatId,title,createdDate,provider,model,repos:[string],stepIds:[stepId],revision,archived,...timestamps}; POST /chats, PATCH /chats/{id}, archive/recover. provider and model are free text; repos holds at most 20 distinct names. stepIds is the complete list of steps a roadmap chat works on (always empty for a work item's chat): every step must belong to the chat's roadmap, a retired step can stay but not be newly assigned, and each assignment change records chat.assign or chat.unassign in that step's history. Agents claim steps by proposing chat.create or chat.update with stepIds.
Chat history (browser session only; an agent credential gets 403 agent_scope) reads the transcripts Claude Code and Codex keep on this machine, never writing them. GET /chats?archived=false lists every agent chat with owner {type,id,title,archived}, steps [{id,title,status,retired}] and transcript {found,source:'claude'|'codex'|null,lastActivityAt,state:'working'|'idle',threads:[{key,name,title,task,parent,model,state,lastActivityAt}],error?} (error set when a transcript exists but cannot be read, without failing the list). GET /chats/{id}/transcript?limit=200&thread=key (limit 1-2000) returns {chat,...transcript,messages,total,more}: the latest limit messages oldest first (thread narrows them to that agent's transcript and what it sent), each {id,thread,at,kind:'user'|'assistant'|'agent'|'tools',author,authorThread?,recipient?,text?,truncated?}, a tools run adding {count,until,tools:[{name,summary}]} for consecutive tool calls. A chatId finds a transcript only in the shape those tools use: a Claude Code session UUID under ~/.claude/projects (CLAUDE_CONFIG_DIR), a Claude desktop local_ session ID resolved to the Claude Code session it runs, or a Codex thread ID under ~/.codex/sessions or archived_sessions (CODEX_HOME). A Claude session includes its subagents; a Codex thread that started agents includes every thread sharing its session. agent messages are the ones agents send each other (SendMessage, subagent prompts, Codex agent messages), named by tracked chat title or desktop session title where known. Tool context, system reminders and tool output are left out, text over 20,000 characters is shortened, each transcript keeps its latest 2,000 messages (older ones still count in total, but more is true only while a larger limit would show earlier kept messages), and a line over 32 MB or not JSON is skipped. A thread is working while its latest turn is open and its file changed in the last 15 minutes.
GitHub references {id,ownerType:'item'|'roadmap',ownerId,kind:'commit'|'pr',url,reference,title,description,chatId,chatTitle,revision,archived,...timestamps}; POST /github, PATCH /github/{id}, archive/recover.
Roadmap questions {id,roadmapId,title,details,answer,status:'open'|'answered',revision,archived,...timestamps}; POST /questions {roadmapId,title,details:''} always opens a question; PATCH /questions/{id} {revision,title?,details?,answer?,status?}; archive/recover. Marking a question answered needs a nonblank answer (422 fields {answer:'required'}); reopening keeps the answer. Roadmap decisions {id,roadmapId,title,rationale,decidedDate,revision,archived,...timestamps}; POST /decisions {roadmapId,title,rationale:'',decidedDate?:date} (today in the configured timezone when omitted or blank); PATCH /decisions/{id} {revision,title?,rationale?,decidedDate?} keeps the date when decidedDate is omitted and rejects a blank one (422 fields {decidedDate:'required'}); archive/recover. details, answer and rationale are Markdown up to 100,000 UTF-8 bytes; titles up to 1,000. Roadmap details list questions oldest first and decisions newest decidedDate first; search indexes both and routes to the roadmap. Agents add them by proposing question.* or decision.* operations with the same fields.
GET /attachments?ownerType=&ownerId=&archived=false metadata envelope; POST /attachments?ownerType=&ownerId=&name= raw bytes Content-Type, 25,000,000 byte max. GET /attachments/{id}?download=1 authenticated bytes. POST archive/recover {revision}. {id,name,mime,size,sha256,revision,archived,ownerType,ownerId,createdAt}. Notes max1,000,000 UTF8 bytes. Paths copy only.

## Roadmaps (plans agent owns exact implementation matching this contract)
GET /roadmaps?archived=false -> list envelope of {id,title,overview,parentId,revision,archived,...}. POST /roadmaps {title,overview:'',steps:[],parentId?:activeRoadmapId}. Roadmaps nest: parentId names the parent roadmap (null at the top level). POST /roadmaps/{id}/move {revision,parentId:id|null} changes only the placement, records roadmap.move history and no version; the parent must be active and neither the roadmap nor one of its sub-roadmaps. Revisions and restores keep the placement, and archiving keeps children's parentId. GET /roadmaps/{id} -> {id,title,overview,parentId,ancestors:[{id,title,archived}] top level first,children:[{id,title,archived}],revision,archived,steps:[{id,title,description,parentId:null,position,status,revision,retired}],versions:[{number,createdAt,note}],workItems:[...],notes,attachments,history}. Steps form a tree with stable UUIDs. POST /roadmaps/{id}/revisions {revision,title,overview,steps:[{id?:uuid,title,description,parentId:null,position}],note:''}. GET /roadmaps/{id}/revisions/{number} -> immutable {number,createdAt,note,title,overview,steps}. POST /roadmaps/{id}/restore {revision,number}. POST archive/recover {revision}. PATCH /steps/{id}/progress {revision,status}; GET /steps/{id}/history. Retired steps retain progress and identity, parent progress derived.
POST /imports/preview?name= raw HTML <=5,000,000 bytes -> {id,title,overview,steps:[...candidate UUIDs...],warnings,sha256}. POST /imports/{id}/commit {title,overview,steps,roadmapId?:existing,revision?:existingRoadmapRevision}; new roadmap from selection or attach original as reference (no merge). Original bytes downloadable via GET /imports/{id}/download with forced attachment. Candidate overview/body Markdown; no original HTML inline.

## Proposals (plans agent)
GET /proposals?status= -> envelope. POST /proposals {title,rationale,operations:[],supersedesId?:uuid} -> draft. {id,title,rationale,status:'draft'|'submitted'|'approved'|'rejected'|'withdrawn',revision,actorId,actorLabel,operations,createdAt,updatedAt,attachments}. PATCH /proposals/{id} {revision,title?,rationale?,operations?} draft only. POST /proposals/{id}/submit|withdraw|approve|reject {revision}. Operations {action:string,payload:object}; existing targets must carry revision in payload. Supported actions: item.create,item.update,item.archive,item.recover,entry.upsert,note.create,note.update,task.create,task.update,roadmap.create,roadmap.revise,roadmap.move,progress.set. entry.upsert payload includes date,itemId,revision. Never execute code, SQL, arbitrary JSON patch, shell, or remote operations. Proposal evidence uploaded via canonical /attachments with ownerType='proposal', ownerId=proposalId, allowed for owning agent on draft only. Approval updates canonical data/history and proposal atomically through supplied dispatch(conn,actor,action,payload). Evidence promoted to canonical proposal association on approval (readable in review); no direct canonical attachment write by agents.

## Backend shared primitive contract
Database(path): .path Path, .connect() -> sqlite3.Connection with sqlite3.Row, foreign keys, .read() context manager, .transaction() BEGIN IMMEDIATE/COMMIT/rollback context manager, .initialize(). Database imports plans.SCHEMA and proposals.SCHEMA during initialize; no circular module imports. backend/worklog/common.py provides AppError(status,code,message,fields=None), uid(), now(), today(timezone), require_revision(row,expected), event(conn,actor,kind,entityId,before,after), unpack(row) (JSON? no assumptions; modules build own records). Actor dict {id,label,kind:'human'|'agent'}.
PlanService(db): list(archived=False), detail(id), version(id,number), history(stepId), preview(data:bytes,name:str,actor), import_commit(id,payload,actor), import_download(id)->(bytes,name), apply(conn,actor,action,payload)->dict. Actions roadmap.create,roadmap.revise,roadmap.move,roadmap.restore,roadmap.archive,roadmap.recover,progress.set. Operations perform validation + events using provided connection; do not commit. Read methods own db.read(). root service will enrich notes/attachments/history separately. Add PlanService.get_step(conn,id) if needed for link validation.
ProposalService(db,dispatch): list(actor,status=None), detail(id,actor), create(payload,actor), update(id,payload,actor), transition(id,verb,payload,actor), check_upload(conn,id,actor), SCHEMA. Methods manage own transactions except check_upload. Human approval invokes dispatch for each operation with originating agent Actor so audit preserves proposer, plus proposal approval event actor=human. Idempotency route wrapper root encloses transaction? Approval service must accept optional connection to transition(...,conn=None) so root can wrap idempotency and transition atomically. Same create(...,conn=None). Agent can only inspect own draft, other submitted proposals readable. Human all.
