# Worklog implementation contract

Owner: root; task WORKLOG-BUILD. Local-only, new repository. Root owns database primitives, work/day/context services and API integration. Plans agent owns plans.py, proposals.py and corresponding tests. Frontend agent owns frontend/. Operations agent owns cli.py, recovery.py, scripts/, README.md and corresponding tests. Shared files require parent coordination. No commits by children.

All API routes start /api/v1. camelCase JSON. UUID ids, integer revision; timestamps UTC ISO strings. Date strings YYYY-MM-DD in configured America/Chicago timezone. States are open, doing, blocked, done. Every mutation sends a JSON object (raw uploads excepted), includes revision for existing records, and an Idempotency-Key header for creates/approval. Error: {error:{code,message,fields?}}. Conflict 409. Envelope lists {items:[...],total:n}; objects returned directly. Session bootstrap POST /session/bootstrap body {} and X-Worklog-Bootstrap: 1 returns {csrfToken,today,timezone}; fetch credentials same-origin, X-CSRF-Token on cookie writes. Agent Bearer credentials cannot mutate canonical endpoints. Health GET /health unauthenticated: {app:'worklog',version,instanceId,dataId,ready:true}. Health outside api prefix.

Final integration additions: bootstrap also returns required dataId, which namespaces all browser drafts/queues/pending idempotency keys. Offline restore rotates dataId and revokes credentials. Legacy/other-context drafts remain untouched and are never imported automatically. /work-items accepts q, roadmapId, bounded limit/offset; list records add isBacklog. POST /work-items/{id}/move {revision:collectionRevision,direction:'up'|'down'} reorders against a server-selected neighbor across pages. Work details include linkedRoadmap {id,title,archived} and linkedStep {id,title,roadmapId,roadmapTitle,retired}. GET /notes/{id}, /tasks/{id}, /references/{id}, /steps/{id} provide bounded review targets. Search results include routeType and routeId. Daily entries retain archived actual work as read-only history. Import commit is idempotent and shares one transaction with search and history. A durable .restore-in-progress.json marker blocks startup after interrupted replacement until an explicit offline restore succeeds.

## Roadmaps (plans agent owns exact implementation matching this contract)
GET /roadmaps?archived=false -> list envelope. POST /roadmaps {title,overview:'',steps:[]}. GET /roadmaps/{id} -> {id,title,overview,revision,archived,steps:[{id,title,description,parentId:null,position,status,revision,retired}],versions:[{number,createdAt,note}],workItems:[...],notes,attachments,history}. Steps form a tree with stable UUIDs. POST /roadmaps/{id}/revisions {revision,title,overview,steps:[{id?:uuid,title,description,parentId:null,position}],note:''}. GET /roadmaps/{id}/revisions/{number} -> immutable {number,createdAt,note,title,overview,steps}. POST /roadmaps/{id}/restore {revision,number}. POST archive/recover {revision}. PATCH /steps/{id}/progress {revision,status}; GET /steps/{id}/history. Retired steps retain progress and identity, parent progress derived.
POST /imports/preview?name= raw HTML <=5,000,000 bytes -> {id,title,overview,steps:[...candidate UUIDs...],warnings,sha256}. POST /imports/{id}/commit {title,overview,steps,roadmapId?:existing,revision?:existingRoadmapRevision}; new roadmap from selection or attach original as reference (no merge). Original bytes downloadable via GET /imports/{id}/download with forced attachment. Candidate overview/body Markdown; no original HTML inline.

## Proposals (plans agent)
GET /proposals?status= -> envelope. POST /proposals {title,rationale,operations:[],supersedesId?:uuid} -> draft. {id,title,rationale,status:'draft'|'submitted'|'approved'|'rejected'|'withdrawn',revision,actorId,actorLabel,operations,createdAt,updatedAt,attachments}. PATCH /proposals/{id} {revision,title?,rationale?,operations?} draft only. POST /proposals/{id}/submit|withdraw|approve|reject {revision}. Operations {action:string,payload:object}; existing targets must carry revision in payload. Supported actions: item.create,item.update,item.archive,item.recover,entry.upsert,note.create,note.update,task.create,task.update,roadmap.create,roadmap.revise,progress.set. entry.upsert payload includes date,itemId,revision. Never execute code, SQL, arbitrary JSON patch, shell, or remote operations. Proposal evidence uploaded via canonical /attachments with ownerType='proposal', ownerId=proposalId, allowed for owning agent on draft only. Approval updates canonical data/history and proposal atomically through supplied dispatch(conn,actor,action,payload). Evidence promoted to canonical proposal association on approval (readable in review); no direct canonical attachment write by agents.

## Backend shared primitive contract

Actor dict {id,label,kind:'human'|'agent'}.
PlanService(db): list(archived=False), detail(id), version(id,number), history(stepId), preview(data:bytes,name:str,actor), import_commit(id,payload,actor), import_download(id)->(bytes,name), apply(conn,actor,action,payload)->dict. Read methods own db.read(). root service will enrich notes/attachments/history separately. Add PlanService.get_step(conn,id) if needed for link validation.
